[v0.6.3] - 2026-11-06
整理内部结构，命令、配置、玩法和数据文件都没有变化。从 v0.6.2 可以直接替换 jar。

一、结构拆分
1. 入口与生命周期拆分
   - DapUrHomiesMod 保留模组入口、配置/权限初始化、内容与命令注册。
   - 新增 ModLifecycle，集中断线清理、唯一 END_SERVER_TICK、输入上升沿检测、
     Mahito 每 tick 驱动及全局关闭清理，既有执行顺序与关闭语义保持不变。
2. 命令类拆分
   - 新增 command/DapCommands 与 command/InteractionCommands，
     分别承接 /dap 和其余交互/帮助/语言命令；命令名称、参数与权限不变。
3. 玩家偏好与冷却公共流程拆分
   - 新增 PlayerPreferences，集中玩家总开关、模块开关与语言的 allows/set 映射。
   - 新增 InteractionCooldowns，集中冷却检查、提示、覆盖解析与写入。
   - 击掌共享冷却和碰拳分别冷却保持各自语义，不混用双方时长解析方式。
4. 大型玩法类职责拆分
   - 新增 DapVisualEffects 承接击掌分级特效。
   - 新增 ThrowTracker 承接延迟投掷速度、飞行/撞墙/落地追踪与投掷免疫。
   - 新增 HumanShieldController 承接人盾 ArmorStand、切换冷却、伤害转移与清理。
   - GrabYeetHandler 保留抓取主流程，盾牌清理仍先于 holding / heldBy 移除。

二、死代码清理与规范化
5. 删除只写不读的 PoseState；GrabbedPlayerControlMixin 继续通过 isHeld 查询 heldBy。
6. 清理无用代码与导入，规范方法职责、命名和包结构；不改变外部契约与玩法参数。

   - 播放前查询 PlayerModelRegistry，用存在同名自定义动画时才用，否则回退内置动画；
   - API 不兼容或动画缺失时输出一条警告，不再静默失败。

   - 优先使用 Permissions.check(Entity, String, boolean)，旧版命令源签名作为回退；
   - 修复签名不匹配导致一直回退文件权限、LuckPerms 实际未生效的问题。

[v0.6.2] - 2026-11-06
基于 v0.6.1，第二轮代码审查后的修复。

一、P0
1. /dap off 未清理运行中状态
   - 关闭仅设置 modEnabled=false，tickAll 被跳过，但 GrabbedPlayerControlMixin
     仍在取消 travel、右键仍被 Mixin 吞掉。
   - 后果：被携带玩家永久无法移动，跳跃挣脱失效，ArmorStand / BossBar 永久残留。
   - 修复：新增 disableModAndCleanup()，关闭前对全部在线玩家执行
     InteractionModules.cleanupAll()，并调用 GrabYeetHandler.fullCleanup() 与
     DapSessionManager.clearAll()。

二、P1
2. 拥抱窗口过短且吞掉碰拳入口
   - 双方需在 2 tick 内互点，人类几乎无法完成；首个点击直接 return PASS，
     导致「双方潜行互瞄头部但未拥抱」时永远无法蓄力碰拳。
   - 修复：窗口放宽到 10 tick（0.5 秒）；首次点击仅记录并继续走潜行分支；
     拥抱成功时调用 DapHandler.cancelCharge() 取消双方待释放蓄力。
3. 蓄力飞踢释放绕过校验
   - releaseCharge() 直接 executeNormalKick，跳过目标接收、领地保护、距离、
     俯视角度与模块开关；DropKick 对范围内所有 LivingEntity 造成伤害且无接收校验。
   - 修复：释放前统一检查 enableKick、canInitiate、冷却；未满蓄力改为复用
     handleKick()；DropKick 对玩家目标检查 canReceive("kick") 与 ProtectionCompat。
4. 飞踢蓄力永不过期
   - purgeExpiredCooldowns() 为空，chargeStartTime 只在手动释放时移除；
     死亡/断线也不清理，下次潜行看脚会立即以旧蓄力触发飞踢。
   - 修复：tick 内扫描到 3 秒自动 releaseCharge()；断线 cleanup 已覆盖。
5. 人盾关闭仍重新骑乘
   - disableShieldMode(holder, true) 执行 startRiding(holder)，乘客同步会覆盖
     tickCarryPositions 的 requestTeleport，造成位置抖动。
   - 修复：删除 reattach 分支，统一不重新骑乘；仅保留提示参数。
6. 盔甲架被外部移除后状态卡死
   - tickCarryPositions 只判断 shieldStands 是否存在；盔甲架被 /kill 或插件删除后
     stand == null 直接 continue，heldBy 仍在，被抱者 travel 被取消且永不重定位。
   - 修复：stand == null || !stand.isAlive() 时自动 disableShieldMode 并回退到直接携带。
7. 跨维度交互
   - InteractionRouter / DapHandler / KickHandler / HugHandler / GrabYeetHandler
     仅用 distanceTo 判断距离，不含维度；同坐标跨维度可推人、出特效、拉人。
   - 修复：所有入口统一校验 getEntityWorld() 相同；DapSession 地面检测也随之安全。
8. 投掷破墙无视领地保护
   - breakBlock(pos, true) 最多破坏 12 格且掉落物品，可被用来拆家。
   - 修复：ProtectionCompat 新增 canBuildAt(player, pos)，投掷撞墙前先校验；
     被保护时不破坏方块（撞墙伤害与反弹仍然生效）。
9. 冷却覆盖对普通碰拳/击掌无效
   - 直接用配置毫秒数设置冷却，绕过 AdminManager.resolveCooldownTicks，
     /dap cooldown set 对 dap 与 highFive 不生效。
   - 修复：普通碰拳使用 resolve(sid,"dap",dapCooldownMs)，
     击掌使用 resolve(sid,"highFive",highFiveCooldownMs)，并补充击掌冷却检查。

三、P2
10. 投掷（yeet）漏清 poseStates，导致抓取姿态残留。
11. 携带时 setVelocity(0,0,0) 未置 knockedBack=true，客户端速度不同步，抖动。
12. 拥抱状态机增加存活、同世界校验；结束时清除本模组施加的缓慢/挖掘疲劳，
    避免拥抱结束后仍持续约 3 秒；startHug 失败不再返回 SUCCESS。
13. 封禁、冷却覆盖仅存内存，重启即失 → 新增 config/dap-ur-homies-admin.json
    持久化（封禁按墙钟到期时间保存，重启仍有效）。
14. /dap ban、/dap unban、/dap cooldown 增加类型合法性校验（未知类型直接拒绝）。
15. /dap off <玩家> 可被该玩家 /dap on 撤销 → 新增管理员强制关闭名单，
    强制关闭优先于管理员绕过，玩家无法自行恢复。
16. 合并两处独立 literal("cooldown") 命令节点，避免依赖 Brigadier 自动合并。
17. 到期清理周期 6000 tick → 200 tick，减少 pendingHighFive / pendingPerfect 滞留。
18. ProtectionCompat 反射捕获 Exception → Throwable，避免第三方类缺失时
    LinkageError 造成 ExceptionInInitializerError。

四、代码规范化
19. 删除 PlayerRidingMixin（重新骑乘移除后已无用途）并从 mixins.json 移除。
20. 删除 GrabYeetHandler 未接线死代码：requestElytraBoost、setAirMovementInput、
    AirMovement、elytraBoostRequests、tickElytraBoosts、tickAirMovement、
    syncHeldRotation、lastSyncedYaw 及其清理逻辑。
21. 清理未使用导入：DapUrHomiesMod(ActionResult)、Lang(UUID)、
    InteractionRouter(Lang/UUID)、SimpleInteractions(TickClock)、
    GrabYeetHandler(LightningEntity/StatusEffectInstance/StatusEffects/Text/Box/PlayerEntity)、
    AdminManager(ServerPlayerEntity)。

[v0.6.1] - 2026-11-06
基于 v0.6.0，全量检查后的一批修复与代码整理。

一、致命/高危修复
1. 双重 tick 驱动（P0）
   - 问题：DapHandler、DapSessionManager、GrabYeetHandler、HugHandler、KickHandler、
     PushHandler、FallCatchHandler、CarryingSlowdown、LaunchedPlayerTracker、
     SimpleInteractions 等多个模块在各自 register() 中注册 END_SERVER_TICK，
     主类 tick 中又逐个调用一次 tick()，导致所有周期逻辑每 tick 执行两次：
     蓄力速度翻倍、冷却计时减半、粒子与音效重复、抓取位置抖动。
     同时 /dap off 只拦截主类分支，模块自注册的 tick 仍然运行，全局开关形同虚设。
   - 修复：register() 一律只注册事件回调，周期逻辑统一由
     interaction/InteractionModules.tickAll(server) 单点驱动；
     主类只保留一个 END_SERVER_TICK，并先判断 modEnabled。
2. 拥抱（Hug）永远无法触发（P0）
   - 问题：InteractionRouter 中潜行分支先命中并 return ActionResult.PASS，
     拥抱判定位于其后，属于不可达代码；且旧的 bothRightClickedWithin /
     recordHugClick 组合时序不可靠。
   - 修复：拥抱判定前移到潜行分支之前，双方潜行 + 互瞄头部 + 2 tick 内各右键一次；
     hugClickTick 改为顺序无关的 hugKey，并每 100 tick 清理超过 40 tick 的过期条目。
3. 管理指令权限绕过（P1）
   - /dap ban、/dap unban、/dap cooldown 的全局分支未校验管理员权限，普通玩家可改全局状态。
   - 修复：统一走 Lang.noPermission(p) 拦截。
4. 交互入口权限缺失（P1）
   - dap / hug / slap / clap / catch 未检查发起者 canInitiate 与目标 canReceive，
     被封禁玩家仍可发起，目标关闭接收仍被打扰。
   - 修复：所有入口补齐发起方开关、封禁、冷却（bypassesCooldown）与目标接收校验。
5. 抓取/投掷/人盾状态错乱（P1）
   - disableShieldMode(holder, reattach) 的 reattach 参数在丢弃/投掷路径被误传为 true，
     重新骑乘导致投掷初速度被原版骑乘逻辑吃掉，玩家扔不出去。
   - 修复：放下/投掷传 false（不再重新骑乘），仅切换人盾时传 true。
   - cleanup() 改为无论 holding 条目是否已存在都强制清理 shieldStands /
     shieldModeActive / shieldSwapCooldown；修复乘客匹配遗漏（getUuid().equals）。
   - 跨世界抓取会残留，改为世界不一致直接 cleanup。
6. 被抓玩家位置滞后（P1）
   - 服务端实体坐标未更新就直接 requestTeleport，客户端收到旧坐标。
   - 修复：先 refreshPositionAndAngles(...) 再 requestTeleport。
7. 并发安全（P1）
   - GrabYeetHandler 的 holding / heldBy / poseStates 被客户端 Mixin（集成服）读取，
     原 HashMap 存在并发读写风险。
   - 修复：全部改为 ConcurrentHashMap；tickHeldPlayers 改为 for-each 遍历 +
     cleanup(hid) + continue，避免遍历中结构修改。

二、功能接线修复
8. 跳跃挣脱（文档已描述但从未接线）
   - 主 tick 检测 player.getPlayerInput().jump() 的上升沿，调用
     GrabYeetHandler.tryEscape(player)（20% 成功率，每次起跳判定一次）。
9. 蓄力飞踢入口不可达
   - 原实现只有「普通踢」，KickHandler.startCharge 无调用点。
   - 修复：潜行 + 看脚部 + 右键第一次开始蓄力，3 秒内再次同操作释放；
     超时自动释放；冷却统一走 bypassesCooldown。
10. 配置项失效
   - adminBypassCooldown：PlayerPermissionManager.bypassesCooldown 未读取，现生效。
   - clapIntervalTicks：ClapLooper.Loop 增加 interval，实际参与节奏推进。
   - globalLang：Lang 全局语言只改内存不落盘，现写入配置并持久化。
   - /dap sound 修改后未保存，现调用 ModConfig.save()。

三、健壮性修复
11. 配置文件损坏容错
    - ModConfig.load() 与 FilePermissionProvider.load() 捕获
      IOException / RuntimeException，单条非法 UUID 或空值跳过，不再导致启动崩溃。
12. 断线清理
    - DISCONNECT 同时清理 handSwingingLastTick、jumpHeldLastTick 与
      InteractionModules.cleanupAll(id)，避免内存泄漏与残留持有关系。

四、代码规范化
13. 删除死代码
    - SpinHandler.java：无任何可达入口（客户端旋转按键在纯服务端不可读），整体删除。
    - PlayerEntityPassengerOffsetMixin.java：空实现，删除并从 mixins.json 移除。
    - PushHandler：pendingJumpPush / pushWindow / startPushWindow / isInPushWindow /
      confirmJumpPush / PUSH_WINDOW_TICKS 等从未被写入的死逻辑全部删除。
    - KickHandler：未使用的 NORMAL_KICK_RANGE 与重复 ServerTickEvents 导入删除。
14. 交互路由重构
    - InteractionRouter 分支顺序固定为：盾/被投掷排除 → 疾跑推搡 → 蓄力/普通碰拳
      → 拥抱 → 潜行（飞踢 / 蓄力碰拳）→ 站立普通碰拳。
15. 帮助文本修正
    - Push 改为「疾跑 + 右键」；Drop 改为「未蓄力左键」；
      DropKick 改为「潜行 + 看脚部 + 右键两次」；版本号更新为 v0.6.1。

[v0.6.0] - 2026-09-22
基于 v0.5.8，修复完美击拳（Perfect Dap）无法触发的问题 + 架构重构降低耦合。

Bug 修复：
1. DapHandler.startCharge() 互相蓄力解禁（P0）
   v0.5.3 引入的 isCharging(target) 检查与完美击拳判定直接矛盾：
   A 蓄力后 B 永远无法开始蓄力，导致「双方同时互相蓄力」状态不可达，触发率为 0%。
   改为仅当对方在蓄力「别人」时才拒绝。
2. 完美击拳改为 pending-release 窗口判定（P1）
   旧逻辑要求双方 chargeStart 相差 ≤2 tick（0.1 秒），人类操作不可能满足。
   新逻辑：满级释放后留下 1.5 秒（PERFECT_WINDOW_TICKS）应答窗口，
   对方在窗口内满级释放（或此刻仍满级蓄力瞄准我）即触发。Mode 0 / Mode 1 统一适用。
3. 完美击拳专属特效：tier3 级特效（爆炸音 + 钟声 + 冲击波击退 + 大量粒子）
   + 双语 "PERFECT DAP / 完美击拳" actionbar。
4. cleanup() / purgeExpiredCooldowns() 覆盖新增的 pendingPerfect 状态。

架构重构：
5. 新增 interaction/InteractionModules.java：模块生命周期注册表，
   主类不再硬编码 12 个 handler 的 register/tick/cleanup/purge 调用。
6. 新增 interaction/PlayerInteractionState.java：跨模块状态门面，
   InteractionRouter 与主类不再直接访问各 handler 的静态状态。
7. DapUrHomiesMod 精简 onInitialize / 断线清理 / tick / purge 流程。
8. /daphelp 版本号更新为 v0.6.0。

完美击拳触发方式：
- Mode 0（按住蓄力）：双方 Shift+右键互相蓄力，都蓄到满级（2.5 秒），
  任一方松开 Shift 释放后，另一方在 1.5 秒内满级释放即可触发；
  双方一直按住到自动释放（3 秒）时若均满级也会直接触发。
- Mode 1（循环蓄力）：一方在峰值（满级）点击释放后，
  另一方在 1.5 秒内于自己的峰值释放即可触发。
